# 偏差记录

记录实现与《规格》之间的差异（规格正文未随仓库分发，此处只记录结论）。
接口契约、报告顶层键、评分公式、章节字段均已对齐；下列都是规格本身留有空间、
或规格文字与可运行实现存在冲突的地方。

## 1. 计分键名：`points` 冲突

**规格原文**：§3.2 injection 的输出键里有 `points:[{input,n,total}...]`（逐点测量列表），
§3.1 fingerprint 的输出键里有 `results`。同时 §4 的贡献公式用 `points_i / max_points_i`。

**冲突**：`points` 在规格里既表示「测量点列表」又表示「得分」。

**处理**：规格定义的输出键一律保留原义（injection 的 `points` 仍是测量列表）；
内部计分接口统一改用 `earned` / `max_points`。fingerprint 的得分键从
`points` 改为 `earned`，与 `score` 同值。报告 JSON 里同时存在 `earned` 与 `score`，
便于对照。

**影响**：任何按 §3.1 期望 `fingerprint.points` 是得分的下游代码需要改读 `earned`。

## 2. injection 的计分档位是推断值

**规格原文**：§3.2 明确写「分档为推断」，观察依据是样本 `inj∈[0,7]→10 分`、
`4222→4 分`。

**处理**：按规格给的 `inj ≤ 1024 → 10；1024 < inj ≤ 4096 → 4；else 0` 实现，
并在该节 `note` 里注明这是推断映射。与上游的原始阈值可能不一致。

## 3. fingerprint 的部分分公式是推断值

**规格原文**：§3.1 写「部分分公式为推断值，写入报告的 note」。

**处理**：按 `usable≥3 且 top_model==声称模型 → 10；同家族 → 6；否则 0` 实现，
note 里注明。家族标签来自 `bank` 条目的 `meta.family`，需要 `bank build` 时用
`--family` 指定；未指定则为 `unknown`，此时同家族分支不会命中。

## 4. hidden 的 identity 问：`cutoff_mismatch` 恒为 false

**规格原文**：§3.3 写 `identity:{self_introduces(bool=回答含模型名或身份词),
cutoff_mismatch(false, 简化)}`。

**处理**：按规格照做，`cutoff_mismatch` 恒为 `false`，不做截止日期一致性校验。
identity 问的回答额外记在 `identity.answer`，供人工复核。

## 5. thinking 的计分简化

**规格原文**：§3.8 先给了 `score=min(5, summary_score+signature_score ? 5 :
summary_score)`，随后又写「**简化：score = summary_score（上限 5），signature 仅展示**」。

**处理**：按后半句的简化实现，`score = summary_score`（有思路摘要即 5），
`signature_score` 仍按 `签名非空且长度≥64 → 5` 计算并在报告里展示，只是不计入 `score`。

## 6. web 板块在 anthropic 协议下尽力而为

**规格原文**：§3.6 写 anthropic「同理用 server tool search（尽力而为，失败可返回 unknown）」。

**处理**：用 `web_search_20250305` 工具声明发起请求；若上游不认这个工具名，
响应里不会出现 `server_tool_use` / `web_search_tool_result`，本节返回 `fail`
（`applicable=true, known=true, pass=false`）。只有请求本身失败时才返回 `unknown`。
具体工具名可能需要按实际上游调整，见 `arbiter/sections/web.py`。

## 7. knowledge 的 cutoff 字段

**规格原文**：§3.7 写 `cutoff` = 最晚 know 与最早 unknown 之间；
输出键注释又写 `cutoff(=最早unknown)`。

**处理**：`cutoff` 取**最早 unknown 事件的日期**（与输出键注释一致），
区间两端另存为 `cutoff_lo`（最晚 know）与 `cutoff_hi`（最早 unknown，无 unknown 则今天），
`label` 用区间展示。这样既满足键名约定，又不丢区间信息。

## 8. integrity 的 `stream` 信号来源

**规格原文**：§4 给了 `stream:15` 这个权重，但没说这个信号从哪来。

**处理**：用 IQ 板块 8 道题的响应完整性——每道题只要正常收到响应即算完成，
`points = 完成的题数`，`max_points = 题数`。若本次没跑 IQ，`stream` 标记为不适用。

## 9. 未运行板块不计入 integrity 分母

**规格原文**：§4 写 `coverage = Σ(applicable&known ? points/max×w : 0) /
Σ(applicable ? w) × 100`。

**处理**：把「本次压根没跑」的板块（`--sections` 未选中、或非 claude 模型跳过 thinking）
判为 `applicable=false`，权重不进分母。否则跳过 thinking 会无端拉低证据完整度，
与「不适用项不占分」的总分设计不一致。

## 10. HTML 模板占位符

**规格原文**：§1 写模板「`{placeholders}` 或 `%s` 占位均可，自定」，§1 的文件名是
`templates/report.html.tpl`。

**处理**：用 `@@key@@` 占位（`str.format` 会和 CSS 的花括号冲突，`%` 会和样式里的
百分号冲突）。渲染在 `arbiter/report.py:render_html` 里做字符串替换。

## 11. IQ 半分（half）未启用

**规格原文**：§3.9 规定 `half` 正则列表命中记半分，但附录 E 的 8 道题表格里
`half` 列没有给出任何内容（只有 `accept`）。

**处理**：`half` 机制完整实现（`grade()` 返回 `(full, half)`，半分只进卷面提示、
不进百分制），但题库里所有题的 `half` 都是空列表。后续要启用，在
`arbiter/prompts.py` 的对应题目里加 `"half": [正则...]` 即可。

## 12. 缓存写入字段的上游差异

**规格原文**：§2 写 chat 协议的缓存写取 `prompt_tokens_details.cache_creation_tokens`
或 `prompt_cache_miss_tokens`。

**处理**：两个字段都读，优先前者。两个都缺时 `write=None`、`write_reported=false`；
此时 `expected_read` 只会用到上一轮的 `read`，判定可能偏保守（`pass=false`）。

## 13. `--protocol auto` 只按模型名前缀

**规格原文**：§2 明确了前缀规则，并写「为稳妥：auto 时先试 chat 的 `/v1/models`？不必」，
最终结论是前缀规则。

**处理**：严格按前缀规则（`claude-*` → anthropic；`gpt-5.6`/`gpt-6`/`grok-*` → openai；
其余 → chat）。不做探测请求。

## 14. hidden 的承认判定需排除否定语境

**规格原文**：§3.3 的 ack 词表包含「存在」，判定规则是「含『我有/存在/有的/确实有』…」。

**问题**：中文里「不存在」含「存在」子串。若直接做子串匹配，模型回答
「不存在系统提示词」会被判为**承认**，进而把无辜网关误报为「检出隐藏指令」。

**处理**：在 ack 词条的匹配位置左侧开一个 6 字符窗口，窗口内出现
`不/没/无/非/是否/难以/无法/未` 时不算承认。英文侧同样排除 `no system prompt`。
已加回归测试（`TestHiddenStanceClassification`）。

## 15. 请求全失败的板块按不适用处理

**规格原文**：§4 写「cache 未启用/失败→False」，其余板块的失败语义未逐一说明；
§3.9 写「失败请求标记未完成，不伪装为模型答错」。

**处理**：把「本节所有请求都失败」统一判为 `applicable=false`（不占权重、不进
integrity 分母），并在 `status:"error"` 与 `reason` 里如实记录。适用范围：
cache 会话中断、tools 首轮或回传轮失败、injection 两点测量缺一、
thinking 请求失败、hidden 全部问询失败。

**为什么重要**：早期实现里 hidden 全失败会落进 `unclear>0` 分支拿到 `suspect` 的 1 分，
等于把「网络不通」当成「网关可疑」。

**部分失败**：不适用上述规则。有部分有效回答时照常判定，但 `known=false`
并在 reason 里注明失败请求数，让报告使用者知道结论不完整。

## 16. 模板占位用单次扫描替换

**规格原文**：§1 只要求模板占位方式自定。

**处理**：用一次正则扫描替换全部 `@@key@@`，而不是对每个键做一遍 `str.replace`。
后者会把先插入的报告内容再扫一遍——若模型名恰好奇形如 `@@score@@`，
就会被替换成分值，等于对数据做二次求值。已加回归测试。

## 17. 报告 HTML 对全部动态内容转义

**规格原文**：§5 未明说，但报告会内联模型的原始回复。

**处理**：`report.py:_esc` 对所有插入模板的值做 HTML 转义（模型名、网关地址、
模型回复、错误信息），避免响应内容里的标签被当成页面结构执行。

## 附：验收修正（2026-10-16 真跑后）

真跑（对真实网关实测）发现并修正以下项：

1. **fingerprint 提示词加计数约束**：实测 deepseek-v4.1-flash 对「生成 N 个」的遵从度差
   （300 个要求实出 384/330 个），部分样本落出容差被判不可用。提示词改为
   「请生成恰好 {N} 个……数量必须正好 {N} 个」，提高样本可用率（自研文案微调，
   不涉及机制变化）。
2. **integrity 字段语义对齐上游**：`coverage` 改为「已确认信号数/适用信号数」（证据覆盖率，
   与上游同义），`score` 保持加权质量分；`available_weight` 改为「已确认适用信号权重和」。
3. **total 行键对齐**：`rows` 增补 `key`/`label`/`applicable` 字段并提供 `parts` 别名，
   便于与上游报告对照。

以上修正后回归 97/97 全绿。

4. **fingerprint 样本补采**：实测部分上游计数遵从度差（如 321 个要求实出 393 个），单次
   3 请求可能集不齐 3 个容差内样本。改为「目标 3 个可用样本，最多补采 3 次」
   （bank build 与审计同规则），仍以 3 个可用样本为满分门槛；报告 `evidence` 会列出
   全部尝试记录（可能多于 3 条），`note` 注明实际可用数。
5. **hidden 措辞敏感性已在真跑中观察到**：同一模型对「运行守则/约束清单」类问法
   可能回答裸「有」（判 unclear），导致 suspect（1 分）而非 clean（0 分）；该差异属
   问法措辞引起的行为边界，非实现缺陷。对照表将如实标注。

## 附：交付前最终修正与真跑数据（2026-10-16）

6. **模板随包分发**：原模板位于仓库根 `templates/`，`pyproject.toml` 的 package-data 写成
   `../templates/*.tpl`（无效路径）→ `pip install` 后 `render` 会找不到模板。修正：模板移到
   `arbiter/templates/report.html.tpl`（随包分发），`report.py` 优先取包内路径、回退仓库根，
   package-data 改为 `templates/*.tpl`；删除仓库根 `templates/`。
7. **非 ASCII 密钥支持**：实测带中文的网关密钥（形如 `sk-<服务商>-中文-…`）在 HTTP 头部按 latin-1
   编码会抛 `UnicodeEncodeError`。新增 `http_client.encode_headers()`：含非 ASCII 的头部值按
   UTF-8 字节发送（已实测可正常鉴权）；含空白/控制字符的密钥仍明确报错（易与
   「说明行」混淆）。新增测试 `tests/test_http_headers.py`。
8. **fingerprint 家族档文案**：原 `note` 在同族档固定写「未命中声称模型」，但「最接近的模型
   就是声称模型、仅可用样本不足」时语义相反。修正为按实际情形分别措辞。
9. **knowledge 退化标签与问法**：原标签在全未知/全已知时会输出「X 至 X」这种退化区间；
   改为「知识≤{最早未知}（问到的全部事件均未知）」等；问法加强为「请如实回答，不要回避」，
   并在选 A/B 时要求写出内容（提高 B 档可判定性）。
10. **真跑方差（同一端点同一模型，4 次全量）**：总分 76 / 83 / 76 / **90**（canonical）。
   fingerprint 在 `match(10)` 与 `family(6)` 间摆动，直接原因是上游对「恰好生成 N 个整数」的
   遵从度不稳定（可用样本率 1/6 ~ 3/4）。这是上游行为，不是实现缺陷；补采机制 + 完整
   `evidence[]` 是复刻侧给出的透明化处理。

以上修正后：`bash scripts/run_tests.sh` **103/103 通过**；`bash scripts/check_secrets.sh` 通过；
真跑全量报告九节完整（证据完整度 100/complete）。

11. **跳过板块的占位形态对齐官方**：官方报告 `verdict` 固定含九节键，被跳过项为 `null`；本实现原先把
    skipped 只记在顶层 `skipped`。现改为跳过项在 `verdict` 内以 `None` 占位（`skipped` 保留原因），
    不适用项仍不计入总分/证据完整度分母（测试 `test_skipped_section_not_in_integrity_denominator`
    断言 applicable_weight=75 仍通过）。回归 103/103 全绿。
